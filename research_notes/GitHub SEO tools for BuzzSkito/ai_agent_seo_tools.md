# Open-source AI-agent SEO tooling on GitHub (Claude Code skills/agents/plugins, SEO MCP servers, LLM SEO workflows): inventory and fit for buzzskito.ca

Research date: 2026-10-21. Method: star counts, forks, last-push dates, creation dates and licenses were read from the GitHub REST API (`api.github.com/search/repositories`, unauthenticated, sorted by stars) on 2026-10-21. "Last push" is GitHub's `pushed_at` (most recent push to any branch); the commit-search endpoint returned HTTP 422 and the shared per-IP core quota ran out, so per-default-branch last-commit dates were NOT pulled (see Gaps). Nothing was installed, cloned or run; READMEs and one SKILL.md were read as text only. Local evidence about this machine's existing setup is cited by file path.

## Q1. Which Claude Code SEO skills/agents/plugins are most starred or discussed, what do they contain (prompts or running code), and are they better than BuzzSkito's own briefs?

### Takeaway
The category exploded in 2026: the top packs are coreyhaines31/marketingskills (55.8K stars, mostly Markdown), AgriciDaniel/claude-seo (19.6K, real Python/Playwright code, 26 sub-skills + 19 subagents) and zubair-trabzada/geo-seo-claude (11.1K, Python + agency-selling funnel). Almost all are generic, agency-oriented packs from solo maintainers or companies selling a hosted product/community. None encode site-specific measured rules like BuzzSkito's briefs and build guards, and several bundle features that conflict with Google policy (Indexing API submission, programmatic page generation).

- Are they better than BuzzSkito's briefs? For writing and fact-checking, no: the packs are site-agnostic and cannot know rules the site measured itself (verbatim Amazon disclosure, US/CA locale split, page roles, Mediavine placement, no AI images). Their real value is code that fetches data the site does not routinely pull (CrUX history, image-level audits, internal link graph joined to GSC), which can be ported as small scripts rather than installed as a pack.
- The most-starred packs are marketing-funnel assets (Skool communities, hosted connectors, partner-funded); popularity signals distribution, not audit quality.

## Q2. Which SEO MCP servers exist beyond GSC and Ahrefs (Bing, DataForSEO, PageSpeed, Trends, Semrush, Screaming Frog)? Official vs community, maintained vs abandoned, cost?

### Takeaway
Vendor-official MCPs now exist for GA4 (Google, experimental), Ahrefs (remote), Semrush (remote), DataForSEO, SE Ranking, SerpApi, Firecrawl, Screaming Frog (native in SEO Spider 24, paid licence) and Chrome DevTools (Google, 53.9K stars). There is NO official Google Search Console, Bing Webmaster or Google Trends MCP: those are community projects, several abandoned. Costs range from free (Google/Bing APIs) to pay-as-you-go (DataForSEO, $50 minimum top-up) to subscription-gated (Semrush, Ahrefs, Screaming Frog).

### Takeaway

### Inferences
- Immediate fix (no new tool): add `"GSC_ALLOW_DESTRUCTIVE": "false"` to the gscServer env block (or update the clone to 0.4.1), and add permission deny rules for `mcp__gscServer__delete_site`, `mcp__gscServer__delete_sitemap` and `mcp__gscServer__add_site`. The site never needs an agent to delete a GSC property.
- No known malicious package specific to SEO MCPs was found, but springvoiceswell/semrush-ai-tool matches the documented lure pattern (stars without forks, days-old history, committed archive, "patch"-style tags, unpinned remote execution) and should be treated as unsafe.
- Safe vetting step before installing any SEO MCP/skill (inference from the sources above):
  1. Prefer vendor-official servers or maintainers with a long public history; treat star spikes on young repos (for example 6.4K stars in 53 days) as unproven.
  2. Read the whole repo as text first: list every script, hook, installer and dependency; grep for network calls, `eval`/`exec`, `curl | bash`, base64 blobs, committed archives, telemetry.
  3. Check write capability and token scope: prefer read-only scopes (`webmasters.readonly`, `analytics.readonly`); refuse hosted connectors that take Google OAuth unless the vendor is already trusted.
  4. Pin an exact version or commit (no `npx -y github:...@latest`, no `@latest` for third-party code); keep `mcp-remote` at 0.1.16 or later if used.
  5. Deny destructive and submission tools in Claude Code permissions; disable telemetry flags; give paid-API servers a separate key with a spend cap.
  6. Re-review on every update (the postmark-mcp backdoor arrived in version 16).

### Gaps
- No SEO-specific malicious MCP package has been publicly confirmed in the sources found; the springvoiceswell assessment is pattern-based, not a code review.
- Upstream mcp-gsc's scope handling in 0.4.1 (read-only vs full) was not confirmed from the README.

- Third-party SERP APIs (DataForSEO, SerpApi) move the scraping to the vendor. Using them does not put BuzzSkito itself in breach of Google's spam policy as written (that targets queries sent to Google), but the Google v. SerpApi suit makes vendor continuity and data access a real business risk; avoid building anything critical on a single SERP vendor.
- The site's growth plan (288 scheduled AI-assisted pages, released about 40 a week with fact-checks and disclosure) is the kind of volume the scaled content policy watches; any tool that writes pages faster without the existing fact-check and photo rules increases that risk. Link-building or directory skills should only draft outreach for human review, consistent with the owner's existing "nothing sent" practice.
