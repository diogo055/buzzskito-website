# Five small moves beat 150 trending tools

Of the more than 150 GitHub SEO projects checked for this report, very few would add anything to buzzskito.ca, and the five moves that would are cheap: lock down our own Search Console server, switch on Google's free Search Console export to BigQuery before the May–August 2027 peak, run the weekly re-inspection of new guides through Google's URL Inspection API, crawl the built site once with a free crawler, and read AI-search referrals in tools we already have. The most urgent problem is on this machine, not on GitHub: the Search Console server Claude uses has its delete-property and delete-sitemap tools switched on, set to "true" outright in one config file and by a faulty code default in the other, with full read-write access to the account, and changing one value in both files closes it. The most-starred projects, led by Claude Code skill packs with 11,000 to 56,000 stars, mostly repackage the Search Console, GA4 and Ahrefs data the site already pulls, and none knows the rules this site measured for itself. Many of the rest cross a line that costs money: every open-source rank tracker depends on scraping Google, several packs push ordinary pages through an Indexing API that Google reserves for job and livestream pages, and any link checker or browser-based tester aimed at the live site would send robot clicks through about 4,500 Amazon links and, once Mediavine launches, generate automated ad impressions. Eight tools are worth holding for a specific later need, and security argues for that restraint: agent tools have already shipped real backdoors, and Snyk found critical problems in 13.4% of the agent skills it audited ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub)).

## Our Search Console server can delete the property today

The Search Console connection Claude uses here is an MCP server (a plug-in that lets Claude call an outside service), copied from the community project AminForou/mcp-gsc on 6 April 2026 (commit `6db6743`). Its code switches on three tools that change the Google account, `add_site`, `delete_site` and `delete_sitemap`, unless told not to: line 51 of `C:\Users\buzzs\Documents\mcp-gsc\gsc_server.py` reads the on/off setting with a default of **"true"**, while the comment on the line above says the default is false. Neither file that starts the server corrects it. `C:\Users\buzzs\.claude.json` leaves the setting out, so the faulty default applies, and `C:\Users\buzzs\.claude\settings.json` sets **`"GSC_ALLOW_DESTRUCTIVE": "true"`** outright. The server also asks Google for the full read-write Search Console permission (line 64), and all three tools sat in Claude's tool list while this report was written.

The risk lies in the combination. The same agents read competitor pages and search results every day, and Claude Code's documentation warns that servers which fetch outside content expose you to prompt injection, meaning instructions hidden in a page ([Claude Code docs](https://code.claude.com/docs/en/mcp)). A booby-trapped page or a plain agent mistake could remove `sc-domain:buzzskito.ca` or its sitemap from the account, and because sessions on this machine sometimes run with permission prompts switched off (the one behind this report did), nothing would ask first. The site never needs an agent to add or delete a property. The project has already fixed its own default: version 0.4.1, released 15 September 2026, treats the setting as **"false"** unless told otherwise, and the 0.4.0 release the same day stopped batch URL inspections from timing out on `sc-domain:` properties like ours and changed how period comparisons compute their percentage changes ([mcp-gsc source](https://github.com/AminForou/mcp-gsc/blob/main/gsc_server.py); [mcp-gsc commits](https://github.com/AminForou/mcp-gsc/commits/main)). Upstream still requests full read-write access.

The fix installs nothing new and takes Claude Code about five minutes, followed by a restart of Claude Code:

| Step | What Claude changes | Why |
|---|---|---|
| 1 | In both files named above, set `"GSC_ALLOW_DESTRUCTIVE": "false"` in the `gscServer` entry's `env` block | The server itself then refuses, whatever permission mode Claude Code runs in. This is the step that cannot be skipped: `manage_sitemaps` can also delete a sitemap, by a route a deny list does not catch |
| 2 | Update `C:\Users\buzzs\Documents\mcp-gsc` to v0.4.1 and reinstall its requirements | A safe default if a config file is ever rewritten, plus the inspection fix the weekly check below depends on. Period comparisons may read differently afterwards |
| 3 | Add the deny list below to `C:\Users\buzzs\.claude\settings.json` | A second lock. Nothing useful is lost, because separate tools list, read and submit sitemaps |
| 4 (optional) | Change the server to Google's read-only permission, `webmasters.readonly`, and sign in again | The tightest setting, but it blocks sitemap submission through Claude and needs a one-line code change |

```json
"permissions": {
  "deny": [
    "mcp__gscServer__delete_site",
    "mcp__gscServer__delete_sitemap",
    "mcp__gscServer__add_site",
    "mcp__gscServer__manage_sitemaps"
  ]
}
```

Confirm the change by reading the settings back, never by calling a delete tool.

## The trending tools mostly repackage data the site already pulls

### Every Search Console tool hits the same 50,000-row ceiling

Every Search Console library and MCP server on GitHub calls the same Search Analytics API, which returns at most **50,000 rows a day per search type** and drops rows when results are grouped by page and query ([Google](https://developers.google.com/webmaster-tools/v1/how-tos/all-your-data)). No wrapper escapes that limit. Google's bulk export to BigQuery, Google's database service, does: it sits outside the daily row limit, writes each day's data into three tables, and keeps the clicks of rare searches while blanking their wording for privacy ([Google Search Central](https://developers.google.com/search/blog/2023/02/bulk-data-export); [Search Console Help](https://support.google.com/webmasters/answer/12917991)). It has **no backfill**, because collection starts the day it is switched on ([Adswerve](https://adswerve.com/blog/send-google-search-console-data-to-bigquery-with-the-bulk-data-export/)), and only a property owner can switch it on. Two points remain unconfirmed: whether it needs a Google Cloud project with billing enabled, and what BigQuery would charge at our size above its free tier.

The GitHub tools still carry four ideas worth copying into our scripts rather than installing. Suganthan's GSC MCP splits image search from web search page by page, using a baseline for image click-through five to six times lower than web, which is the right lens for photo-ID pages ([Suganthan's GSC MCP](https://github.com/Suganthan-Mohanadasan/Suganthans-GSC-MCP)); the installed server already accepts an image search type, so this needs no new software. SEOMonster scores click-through gaps against a curve built from the site's own positions instead of an industry average ([SEOMonster](https://github.com/avansaber/seo-monster)). Suganthan's `traffic_drops` separates a ranking loss from a click-through collapse and from falling demand, and iannuttall's `seo compare` lays Google's updates over before-and-after windows ([iannuttall/seo](https://github.com/iannuttall/seo)). Two cautions travel with all of them. Decay detectors that compare back-to-back 30-day windows will flag every mosquito and tick page each September, so a seasonal site must judge decay year over year. And any year-over-year baseline from before about 10 September 2025 is distorted, because Google stopped serving 100-result pages then and 87.7% of 319 properties in one sample saw impressions drop ([Search Engine Land](https://searchengineland.com/google-num100-impact-data-462231)).

The remaining data gaps are narrow. Rank trackers would add a daily single-location snapshot and competitor positions, at roughly $6 to $40 a month for 200 keywords checked daily on page one through the scraping services SerpBear lists ([SerpBear](https://github.com/towfiqi/serpbear)), while Search Console already reports official average positions by country for every search with impressions. Google's official GA4 MCP is maintained and read-only, but it would only make the GA4 Data API access the site already has conversational ([google-analytics-mcp](https://github.com/googleanalytics/google-analytics-mcp)). Bing data (searches, Bing keyword volumes, inbound links) is genuinely new, but Bing currently refuses the site's IndexNow pings, most likely because the Bing Webmaster ownership lapsed, so a Bing MCP would return errors until that is repaired ([mcp-server-bwt](https://github.com/zizzfizzix/mcp-server-bwt)). Google Trends has no clean source: the official Trends API is an alpha open only by application ([PPC Land](https://ppc.land/google-opens-alpha-testing-for-new-trends-api-targeting-developers-and-journalists/)). Per-search SERP composition (image packs, People Also Ask, AI Overview citations) is the one paid dataset with a direct line to moving pages from positions 7–10 into the top 3; DataForSEO returns it from $0.0006 a results page ([DataForSEO](https://dataforseo.com/update/ai-overview-in-google-serp-api); [DataForSEO pricing](https://dataforseo.com/pricing)), but Ahrefs' `serp-overview`, already paid for, should be checked first.

### A crawl and Google's inspector see what the build guards cannot

The build guards enforce the site's own rules: sitemap and canonical consistency, Amazon, ads, photo credits. A crawl, a program that visits every page the way a search engine does, checks the finished pages for a different class of fault: internal links that pass through redirects (about 20 are already known), sitemap pages nothing links to, click depth, duplicate titles and descriptions across hundreds of similar pest articles, thin pages, images without alt text or size attributes, broken hreflang return links on the seven regional pairs, and canonicals (a page's declared official address) that point at redirects. SEOnaut documents every one of these among roughly 70 issue types ([SEOnaut issue list](https://github.com/StJudeWasHere/seonaut/blob/main/translations/translation.en.yaml)). It needs Docker and MySQL to run here, and its free hosted tier stops at 500 URLs, so one month of the $9 plan would cover our ~730 ([seonaut.org](https://seonaut.org/)). SiteOne Crawler is the easy alternative: a single Windows program with an HTML report, polite defaults of 3 workers and 10 requests a second, and a sitemap-only mode, though its README does not list its SEO checks in comparable detail ([SiteOne Crawler](https://github.com/janreges/siteone-crawler)). linkinator supplies the redirect list: `--redirects=warn` reports every link that bounces and `--skip` keeps it off Amazon, but its default of 100 simultaneous connections has to come down ([linkinator](https://github.com/JustinBeckwith/linkinator)). None of these runs page scripts in its default mode, so a crawl of the local build, or a polite pass over the live site, never touches the ads.

What no open-source tool can show is the copy of a page Google actually stored, which is the heart of the page-keeper problem. Google's URL Inspection API can: it reports the canonical Google chose next to the one the page declares, and its quota of 2,000 inspections a day per site covers the whole site in one day ([URL Inspection result](https://developers.google.com/webmaster-tools/v1/urlInspection.index/UrlInspectionResult); [API limits](https://developers.google.com/webmaster-tools/limits)). Rendertron, Google's old rendering service, is archived ([Rendertron](https://github.com/GoogleChrome/rendertron)). For faults that reproduce today, such as a canonical that disappears after JavaScript runs, the SEOmator CLI is the only open-source tool found with explicit raw-versus-rendered checks, but it is nine months old and run by a vendor ([SEOmator CLI](https://github.com/seo-skills/seo-audit-skill)).

Schema and speed tools each come with a catch. Google retired FAQ rich results on 7 May 2026 and HowTo results in September 2023, so a validator's FAQ or HowTo "pass" no longer predicts any rich result, and the FAQ and HowTo markup on the site's pages earns none, though nothing found says it does harm ([Google FAQPage docs](https://developers.google.com/search/docs/appearance/structured-data/faqpage)). Adobe's structured-data-validator is the one maintained library that encodes Google's own requirements, with handlers for breadcrumbs, images, organizations and reviews but none for articles, FAQs or local businesses ([Adobe validator](https://github.com/adobe/structured-data-validator)). Unlighthouse runs the same Lighthouse engine as `scripts/measure-speed.mjs`, so it adds whole-site coverage rather than accuracy, and its defaults (200 pages, no throttling on localhost) must change before its numbers compare with the 3.2-second baseline ([Unlighthouse config](https://unlighthouse.dev/api-doc/config)). Real-visitor speed comes from field data instead: the free CrUX API, or the web-vitals library sending each page's LCP, INP and CLS into GA4, which would give Claude per-page numbers that only the owner can see in Vercel today ([CrUX API](https://developer.chrome.com/docs/crux/api); [web-vitals](https://github.com/GoogleChrome/web-vitals)). Image SEO needs no separate tool: the crawl's image checks plus Search Console's image-search data cover it.

### Skill packs and link tools know less than the site's own briefs

The 2026 boom in Claude Code SEO packs is real: marketingskills reached 55,823 stars in nine months, and claude-seo doubled from 9,461 stars in June to 19,570 in October ([marketingskills](https://github.com/coreyhaines31/marketingskills); [Pasquale Pillitteri](https://pasqualepillitteri.it/en/news/5860/claude-seo-claude-blog-open-source-skills); [claude-seo](https://github.com/AgriciDaniel/claude-seo)). Most are Markdown prompts or generic code from single maintainers who sell a community, an agency service or a hosted product, and the research found no independent test of any pack's audit accuracy ([StudioHawk](https://studiohawk.com.au/blog/claude-seo/)). None can know the rules this site measured for itself: the verbatim Amazon disclosure, one store per page, the traffic-versus-service page roles, Mediavine's placement limits, real photos only. claude-seo is the one worth reading, because it has working code for CrUX and PageSpeed pulls, rendered-page checks and image audits that Claude could port as small scripts. Installing it wholesale would bring up to 17 parallel Opus agents per audit, which its README warns raises the cost, and a `seo google index` command that sends any URL to Google's Indexing API with only a warning ([claude-seo Google skill](https://raw.githubusercontent.com/AgriciDaniel/claude-seo/main/skills/seo-google/SKILL.md)).

Internal linking has no popular, maintained open-source semantic tool at all. The repos that link by meaning have 1 to 23 stars, run only on WordPress, or are research code such as WebKnoGraph ([WebKnoGraph](https://github.com/martech-engineer/WebKnoGraph)), and the best-known free option, iannuttall's `internal-links`, matches shared words much as our recirculation already does ([seoskill.dev docs](https://seoskill.dev/docs/internal-links)). With a median of 13 links per page, inside the 10–19 range this site measured as a plateau, a tool could change which links we pick but not how many pay. The cheap test is an embedding audit: score every current Next and Related pair with the free sentence-transformers library on this PC and hand-review the weakest, starting with the 174 pages whose Next article points back at them ([sentence-transformers](https://github.com/huggingface/sentence-transformers)).

Keyword clustering follows the same pattern. Practitioners use free embeddings for the bulk grouping and shared top-10 results only to decide whether two searches need one page or two, and no independent benchmark ranks the methods ([thruuu](https://thruuu.com/blog/semantic-keyword-clustering/)). Our Search Console page-and-search pairs already show which of our pages Google serves for each search, which is the overlap signal for free, and Search Console's own AI-built Query groups, rolling out to high-volume properties first, would do the grouping at no cost if it appears for ours ([Google Search Central](https://developers.google.com/search/blog/2025/10/search-console-query-groups)). Programmatic-SEO templates for Next.js add nothing to the JSON-to-GuidePage pipeline, which already has fact-checks, photo rules and release gates.

### AI answers send 0.3% of visits, so trackers rarely pay

About two dozen maintained open-source AI-visibility trackers exist, almost all under 14 months old with 20 to 500 stars. They reach the AI engines in three ways: official APIs with web search switched on, consumer-app answers bought from scraping vendors, or the user's own logged-in browser sessions. Google's AI Overviews, AI Mode and Microsoft Copilot have no answer API, so every tool covering them relies on a scraper ([limelit](https://github.com/limelit-co/open)). None of the routes yields a reliable ranking. A 1,000-prompt study by Surfer, which sells scraped tracking, found brand mentions overlapped only 15.5–23.8% between the API and the consumer app, and ChatGPT's cited domains overlapped just 4.8% ([Surfer](https://surferseo.com/blog/llm-scraped-ai-answers-vs-api-results/)). A weekly sample is noisy too, as geo-score's own example shows: 4 citations in 11 answers, with a confidence range of 8% to 75% ([geo-score](https://github.com/jianruntech/geo-score)).

The bigger reason to hold off is the size of the prize. Across 74,752 sites in March 2026, AI chatbots sent **0.28% of visits**, while Google sent about a hundred times more ([Ahrefs](https://ahrefs.com/blog/ai-chatbot-traffic/)). AI Overviews cut clicks rather than add them: across 300,000 keywords the top result's click-through ran 58% lower when one appeared ([Ahrefs](https://ahrefs.com/blog/ai-overviews-reduce-clicks-update/)), and the first randomized study measured 39.8% fewer outbound organic clicks ([PPC Land](https://ppc.land/ai-overviews-cut-publisher-clicks-39-8-in-first-randomized-study/)). Display ads and Amazon pay only when a reader lands on our page, so a citation without a click earns nothing, and Google states that optimizing for its AI features is still SEO ([Google Search Central](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)). Tracking 100 prompts a week across six AI surfaces through official APIs would cost roughly $17–45 a month by our arithmetic from published prices, against $129–295 a month for commercial trackers ([elmo](https://github.com/elmohq/elmo); [geo-aeo-tracker](https://github.com/danishashko/geo-aeo-tracker)). The one use with a plausible payoff is a small seasonal check of GTA service searches, where an AI recommendation is high-intent. The same evidence retires llms.txt tooling: in Ahrefs' May 2026 server data for 137,210 domains, **97% of llms.txt files received no requests at all**, and the bots that fetch pages for AI answers made 1.1% of the requests there were ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)). Keeping the existing file costs nothing; improving it gains nothing.

Measuring AI search needs no new tool. GA4 already sorts visits from ChatGPT, Gemini, Copilot and similar assistants into a default "AI Assistant" channel ([Google Analytics Help](https://support.google.com/analytics/answer/9756891?hl=en)), and a source filter for perplexity.ai and claude.ai catches visits it may file under Referral. Search Console added AI Overview and AI Mode impression reports in June 2026, for a subset of sites ([Google Search Central](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports)). Ahrefs Bot Analytics, free during its beta, shows which pages AI crawlers fetch, but on Vercel it needs a log drain, a Pro or Enterprise feature ([Ahrefs docs](https://docs.ahrefs.com/en/bot-analytics/docs/vercel)). That raises a side question worth one check, because Vercel's Hobby plan is for non-commercial personal use and counts ad- or affiliate-funded sites as commercial ([Vercel](https://vercel.com/docs/limits/fair-use-guidelines)). One housekeeping item surfaced too: CLAUDE.md says robots.txt blocks GPTBot and CCBot, but `app/robots.ts` has allowed both since the owner's 16 July 2026 decision, so CLAUDE.md needs correcting.

## Rank trackers scrape Google, and link checkers click Amazon

Google's spam policies, last updated 28 August 2026, name three things popular SEO tools automate: sending automated queries to Google, including scraping results to check rankings; using generative AI to produce many pages that add nothing for users; and using programs or services to create links ([Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies)). The Indexing API, a channel for asking Google to crawl a page quickly, is limited to job postings and livestream videos, runs every submission through spam detection, and can be withdrawn from abusers ([Indexing API](https://developers.google.com/search/apis/indexing-api/v3/quickstart)). Buying scraped results from a vendor such as SerpApi or DataForSEO shifts the act to the vendor, since the policy targets whoever sends the queries, but ties the site to companies under legal fire: Google sued SerpApi in December 2025, a judge dismissed Google's anti-circumvention claims over ordinary search results on 20 July 2026, and Google has renewed the fight ([Search Engine Journal](https://searchenginejournal.com/court-dismisses-googles-dmca-claims-against-serpapi/583033); [MediaPost](https://www.mediapost.com/publications/article/417185/google-renews-battle-with-serpapi-over-scraping.html)). Ahrefs, for its part, does not permit reaching its MCP through custom scripts or bridges ([Ahrefs docs](https://docs.ahrefs.com/mcp/docs/introduction)).

Two rules bite closer to home because they guard the site's income. Amazon.ca's Associates policies forbid generating clicks or Amazon sessions artificially, including by a robot or software program (Participation Requirement 6(s)), and an unfiltered link check would push thousands of automated requests through the site's tagged links ([Amazon.ca Associates policies](https://associates.amazon.ca/help/operating/policies)). Once Mediavine is live, any tool that loads pages in a real browser (Lighthouse, Unlighthouse, Lighthouse CI, browser-mode crawlers) will also load ads. Lighthouse presents itself as an ordinary Android phone, so those impressions would not be filtered as a declared bot and fit Google's definition of invalid traffic ([Lighthouse constants](https://github.com/GoogleChrome/lighthouse/blob/main/core/config/constants.js); [Google Ad Manager Help](https://support.google.com/admanager/answer/12331294)). Mediavine's own rule on publishers speed-testing their pages was not found, so ask them before the first post-launch speed run, and until then test the local build with ads off, or the live site before launch.

The third exposure is the site's own pace, which no GitHub tool measures. Several hundred scheduled AI-assisted pages released about 40 a week fall under the scaled-content policy, which judges added value rather than method; the fact-check gate, real photos and AI disclosure are what separate that program from the template generators on the skip list. Any tool that writes faster by skipping them, or that "humanizes" text to dodge AI detection, erodes that defence, and link-building or directory-submission skills belong in draft-only mode, as the current outreach drafts already are.

| Loads live ad pages in a browser | Invalid ad traffic | Lighthouse, Unlighthouse, Lighthouse CI, browser-mode crawlers |
| Drives logged-in ChatGPT or Claude sessions | OpenAI Terms of Use ([OpenAI](https://openai.com/en-GB/policies/terms-of-use/)) | oneglanse, habibi |
| Lifts Ahrefs data or bridges its MCP | Ahrefs terms; CAPTCHA bypass | cnych/seo-mcp, egebese/dataseo-mcp, custom MCP bridges |

## One in seven audited agent skills carried a critical flaw

The agent-tool ecosystem has already been attacked in the ways that matter here. A fake `postmark-mcp` package on npm behaved for 15 versions, then version 1.0.16 quietly copied every email to the attacker, with about 1,643 downloads before removal ([The Hacker News](https://thehackernews.com/2025/09/first-malicious-mcp-server-found.html)). CVE-2025-6514 let a malicious remote server run commands on a Windows PC through the `mcp-remote` bridge; it was rated 9.6 out of 10 and fixed in 0.1.16 ([JFrog](https://jfrog.com/blog/2025-6514-critical-mcp-remote-rce-vulnerability/)). Snyk's audit of 3,984 published agent skills found critical issues, including malware, prompt injection and exposed secrets, in 534 of them ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub)), and OWASP documents a campaign of 1,184 malicious skills pushed through 12 hijacked publisher accounts in January 2026 ([OWASP](https://owasp.org/www-project-agentic-skills-top-10/case-studies)). Stars vouch for none of it: a peer-reviewed study counts about six million suspected fake GitHub stars, mostly promoting short-lived malware and phishing repos ([arXiv](https://arxiv.org/abs/2412.13459)), and the official MCP Registry checks who owns a name but leaves security scanning to others ([MCP Registry](https://modelcontextprotocol.io/registry/about)).

Several SEO projects in this research show the warning signs. springvoiceswell/semrush-ai-tool has 536 stars but no forks, three commits, a committed zip archive, "semrush-patch" tags and an install line that runs whatever is on GitHub at every launch ([repo](https://github.com/springvoiceswell/semrush-ai-tool)). geo-seo-claude installs by piping a downloaded script straight into the shell ([geo-seo-claude](https://github.com/zubair-trabzada/geo-seo-claude)), and claude-seo's Windows installer runs PowerShell with its execution policy bypassed, then installs Chromium, a Python environment and hooks that fire on events; claude-seo also had to fix a credential-injection flaw and request-forgery bypasses this year ([claude-seo](https://github.com/AgriciDaniel/claude-seo)). Hosted "free" connectors ask for something worse than running code: Ryze and NotFair hold your Google sign-in on their servers, and NotFair's connector can change Google Ads budgets and WordPress plugins ([Ryze](https://github.com/Ryze-AI-Adgent/open-seo-mcp-skills); [NotFair](https://github.com/nowork-studio/notfair-plugin)).

On this machine the stakes are concrete. Anything installed runs as the owner's Windows user, so it can read what Claude reads: the Google sign-in files for Search Console and GA4 in `C:\Users\buzzs\Documents\mcp-gsc`, and API keys stored in plain text in Claude's settings files. Several existing MCP servers already start with `npx -y` and no pinned version, which runs whatever was published last. That is tolerable for packages from the official MCP and Playwright projects, but it is the same path the postmark backdoor travelled, so no third-party SEO server should start that way. Anthropic's own advice is to install skills only from trusted sources and to audit the rest, starting with bundled scripts and anything that reaches the network ([Anthropic](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)). Before any new SEO tool runs here, Claude should put it through six checks:

| Check | In plain words |
|---|---|
| Who is behind it | Prefer the vendor's own server (Google, the Chrome team, Ahrefs, DataForSEO) or a maintainer with years of public history; treat thousands of stars on a weeks-old repo as advertising |
| Read it before running it | Have Claude read every script, installer, hook and dependency as text first, looking for network calls, pipe-to-shell installs, encoded blobs, bundled archives and telemetry |
| What it can change | Prefer read-only Google permissions (`webmasters.readonly`, `analytics.readonly`); refuse connectors that keep our Google sign-in on someone else's server |
| Pin the version | Install one exact version or commit, never "latest" or straight from GitHub; keep `mcp-remote` at 0.1.16 or later if it is ever used |
| Fence it in | Deny delete and submit tools in Claude Code, switch off telemetry, give any paid API its own key with a spending cap, and keep it away from Amazon links and live ad pages |
| Re-check every update | The postmark backdoor arrived in version 16, after 15 clean ones |

## Conclusion

The research changes the question. The site's edge is not a missing tool but the rules it has already measured and wired into its build; the trending packs are built for agencies that have no such rules, and their star counts track Claude Code's 2026 boom and some marketing funnels rather than search results. What the site lacks is mostly data Google gives away (the bulk export, URL inspection, the AI performance report) and one honest look at its finished pages through a crawler. The larger danger runs the other way: every new tool should be judged first on what it can change, delete or click, because the income rests on a Search Console property, an Amazon tag and, soon, a Mediavine account, and a careless tool can damage any of them faster than a good one can grow traffic.

Timing sets the order. The bulk export cannot be backfilled, so starting it this month is the only way to hold a complete record of the 2027 season the goal depends on; the window for whole-site browser testing without ad risk closes when Mediavine launches; and AI-answer tracking has a plausible payoff only for GTA service searches between May and July. Four unknowns could shift parts of this ranking: which Vercel plan the site is on, whether our Ahrefs plan includes Brand Radar, whether the BigQuery export needs a billing account, and how Mediavine wants publishers to speed-test pages while ads run.
